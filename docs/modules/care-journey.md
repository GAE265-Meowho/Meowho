## 目的及本次成果
使用者已授權跳過紙上走查，直接建立可玩的最小原型。本分支新增獨立示範入口 `/care-journey`，不影響 `main`、首頁、真實領養流程或 Supabase。

- `src/lib/care-journey/engine.ts`：虛構貓資料、個體需求、配置更新、四階段／未來預演隔離、照護承諾。
- `src/lib/care-journey/engine.test.ts`：基本 Vitest 案例。
- `src/app/care-journey/page.tsx`：手機友善的示範互動頁；房間為**2.5D 示意**，尚未提供真實拖放、尺寸／路線安全驗證。
- `src/app/care-journey/care-journey.css`：沿用團隊設計 token。

## 體驗與範圍
1. 同家庭、同初始用品配置切換小禾與阿栗，依不同交接要求完成不同用品任務。
2. 幼年使用獨立示範幼貓米粒；成年保留目前個體；熟齡與老年以目前個體的**未來假設**進行任務。
3. 階段任務會新增待確認承諾；可把未來準備待辦帶回現況，但不把年齡或未來事實回寫目前個體。
4. 自由文字目前只記錄輸入作為提案，不做 AI 語意解析、並**不會當成已確認承接**。
5. 不做真實個體、醫療預測、真實收費服務、領養資格判定或完整財務估算。

## 目前限制（請勿誤稱完成）
- 尚未跑本機 `npm test`／`npm run typecheck`／`npm run lint`／`npm run build`；提交後請以 CI 或 Codespaces 執行。
- 四階段現為第一版互動任務與承諾紀錄，尚未形成完整劇情、多事件編排或真正 AI Care Director。
- 房間是展示型平面配置，**不是**已實作的格網合法性引擎、3D 或 AR。
- 尚未支援儲存重新整理後進度、Supabase 整合、真實貓咪 Avatar、模型推論與 Evals。
- 團隊既有 M08 文件／首頁仍有「7 天虛擬試養」描述；本分支**未擅自改寫組長決策**。整合前需確認新版生命歷程玩法是否取代該文案。

## 後續建議
先在 PR 上驗證型別、測試及實際手機畫面。之後優先做一條真正可驗證的方案：配對個體交接 → 時間與支援確認 → 規則檢查 → 狀態更新。再討論模型對話的接入，不要先做四套獨立 3D 關卡。
