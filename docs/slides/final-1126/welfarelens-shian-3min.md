## 投影片 1｜一段居家影片，看見入住前的風險

### 00:00–01:21｜產品價值（45%，約 81 秒）

接下來介紹我負責的 WelfareLens，也就是 AI 居家安全健檢。

在領養貓咪以前，我們通常會準備飼料、貓砂和用品，但有個問題很容易忽略：**自己住得習慣的房間，不一定已經準備好迎接貓咪。**

例如牆邊垂落的電線、窗簾拉繩，飼主每天都看得到，卻未必意識到貓可能接觸或纏繞。

WelfareLens 想做的，就是把「我家到底哪裡要先改？」變成可以採取行動的答案。

使用者只要上傳一段居家影片，系統就會整理出畫面中可見的潛在風險，附上原始圖片、位置和具體改善建議，並產生改善前後的模擬對照。

請看這個真實報告案例：在影片第 **63.05 秒**，AI 標記了左側牆面垂落的線材。**橘色實線**是 AI 估計的風險範圍；**綠色虛線**是改善模擬的場景對位區域。下方還能看到局部整理方式。

這些圖不是宣稱「家裡已經安全」，而是讓使用者先理解問題，再親自收整、現場確認。**產品價值就是從不知道該改哪裡，變成知道可以先做什麼。**

## 投影片 2｜讓 AI 分析可信、穩定、有效率

### 01:21–02:42｜技術亮點（45%，約 81 秒）

要把這個體驗做成真正能用的產品，不能只是把影片丟給 AI，還必須處理三個工程問題。

**第一，結果要有依據。** 我們用 FFmpeg 從影片挑選最多八張代表影格，再交給 Azure 視覺模型分析。模型輸出會透過結構化格式與 Zod 驗證，並保留來源時間和 SHA-256，讓報告能對回原始影格。**雜湊用來確認引用關聯，不代表 AI 一定判斷正確。**

**第二，分析要穩定交付。** 影片處理可能需要數分鐘，所以網站先建立工作，交給 PostgreSQL Queue 和 Docker Worker 背景執行。Scoped Claim 限制領件權限，Lease 和 Attempt 用來管理執行狀態，避免過期結果覆寫。完成後，報告仍必須通過授權檢查才能讀取。

**第三，等待模型的時間要善用。** 改善圖片改成雙路並行，讓等待模型回應的時間可以重疊；同時控制請求起送間隔，避免超出部署配額。

這些設計的目的，都是讓使用者拿到**有證據、能等待、可安全檢視**的改善報告，而不只是 AI 的一段回答。

### 02:42–03:00｜實測成果（10%，約 18 秒）

最後用實測驗證。固定六件改圖任務，從單路 **185 秒**縮短到雙路 **101 秒**，**改圖階段耗時降低 45.34%**；這不是全流程加速率。正式站也完成單筆串接驗收，約 **2.4 秒領件**，本機 Docker Worker 約 **4 分 22 秒**完成。

## 評審追問

**為什麼不直接逐幀分析？**  
逐幀送入容易有重複內容和較高的模型成本；代表影格讓分析規模有上限，但也意味結果只能涵蓋取樣畫面。

**有圖片框線，就表示 AI 找得很準嗎？**  
不能這樣說。橘色實線是模型估計的危害位置；綠色虛線用來標示改善圖的場景對位範圍，並非經人工標註驗證的偵測精度。

**SHA-256 是拿來證明什麼？**  
證明報告引用的影格與原始影格的內容關聯和完整性，**不能證明模型推論正確**。

**Queue 為什麼比同步 API 合適？**  
分鐘級作業適合非同步執行，可管理工作狀態、授權與完成後的結果交付。

**為什麼不用三路並行？**  
在固定六件改圖的受控測試中，雙路已帶來主要效益；第三路的邊際改善更小，還要考慮配額。

**有沒有在雲端正式常駐 Worker？**  
單筆 E2E 驗收是**本機 Linux AMD64 Docker Worker 串接正式網站**；不應當成已驗證雲端常駐與長期負載。
