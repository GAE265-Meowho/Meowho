# WelfareLens V3｜世安 3 分鐘發表講稿（現場切正式網站）

> 配合 [個人兩頁 HTML 簡報](./welfarelens-shian-3min.html)，以及 [團隊總簡報](./Meowho_成果報告_1126.html)。**產品價值 81 秒（45%）／技術亮點 81 秒（45%）／實測成果 18 秒（10%）**。時間包含切換真實網站與 PDF 的操作，不另加 Demo 時間。請實際計時試講。

## 現場操作前先準備（不計入 3 分鐘）

- 用已授權的正式站帳號登入，先開好該喵戶 **已完成的真實安全檢測報告**。入口為「我的喵戶 → AI 居家環境安全檢測 → 查看報告」。若該筆有私有 HTML 圖文摘要，點「查看報告」會開啟主站授權的摘要介面。
- **另外開好完整 PDF**，或確認該報告的「下載完整 PDF」功能可正常使用。PDF 是與主網站摘要分開的檔案與檢視流程，不要當成網站摘要頁。
- 確認是真實影片生成的報告；**不要使用網站「開始檢測」產生的示範報告來宣稱是真實 AI 分析**。
- 切換前確認投影畫面不會露出帳號、個資、住址或未授權的居家影像；若網站或 PDF 無法開啟，使用投影片中已標明為 PDF 案例的四張圖片備援。

## 第一頁｜網站看重點，PDF 看完整證據

### 00:00–00:20｜產品問題與解法（20 秒）

接下來是我負責的 WelfareLens，也就是 AI 居家安全檢測。

準備領養貓咪時，我們會買貓砂和飼料，但可能忽略每天都看得到的危險：例如外露電線或垂落的拉繩。

我們希望讓使用者上傳一段居家影片，就能知道**家裡哪些地方需要先改善**。

### 00:20–01:02｜切換正式網站，展示「主站摘要」（42 秒）

**〔切換到已登入的真實網站安全報告〕**

這裡是主網站實際呈現的**安全檢測摘要**，不是 PDF。

使用者先看到哪些項目需要改善；點開其中一個風險，可以看到可能造成的影響、具體建議，以及哪些情況必須現場確認。

我想強調的是，使用者不需要讀完整本技術報告，就能先理解「這個位置為什麼有風險、我應該做什麼」。

**〔停在一項風險與建議，不逐項滑完〕**

### 01:02–01:21｜展示「獨立完整 PDF」（19 秒）

**〔切到另一個 PDF 分頁，或回到第一頁右側的 PDF 照片〕**

如果需要完整細節，可以另外開啟或下載**完整 PDF**。

這份實際案例在影片第 **63.05 秒**：左邊橘色框是 AI 估計的線材風險位置，右邊綠色虛線是改善模擬的場景對位範圍，下方還有局部前後對照。

**它是改善建議，不是已完成改善或安全認證。**

## 第二頁｜讓 AI 分析可信、穩定、有效率

### 01:21–02:42｜技術亮點（81 秒）

**〔切回團隊總簡報第二頁〕**

這個產品真正的工程難點，不只是 AI 能不能回答，而是**讓網站摘要有依據、完整 PDF 能安全交付**。

**第一，可信。** 我們用 FFmpeg 挑選最多八張代表影格，交給 Azure 視覺模型分析；透過結構化資料與 Zod 驗證格式，再用時間戳和 SHA-256 對應原始證據。這能幫助追溯引用來源，但不代表模型判斷一定正確。

**第二，可靠。** 因為分析會花數分鐘，我們使用 PostgreSQL Queue 與 Docker Worker 在背景處理。Scoped Claim 限制工作領取範圍，Lease 和 Attempt 管理執行狀態，避免過期結果覆寫。主站摘要與完整 PDF 走不同的呈現方式，讀取時仍要檢查授權。

**第三，效率。** 改善圖採雙路並行，把等待 AI 回應的時間重疊，同時保留至少十二秒的請求起送間隔，控制共用模型的配額。

我們的目標，是讓使用者先看得懂摘要，有需要再深入完整 PDF，而不是直接被大量技術內容淹沒。

### 02:42–03:00｜實測成果（18 秒）

最後是實測。相同六件改圖任務，單路中位數 **185 秒**，雙路 **101 秒**，**改圖階段耗時降低 45.34%**；這不是整套系統的加速率。正式站也完成單筆串接驗收，約 **2.4 秒領件**，本機 Docker Worker 約 **4 分 22 秒**完成。

## 評審問答

**主網站的摘要，和 PDF 是不是同一個畫面？**  
不是。主網站提供授權後的摘要／互動式查看體驗，讓使用者先看到需要改善的風險與建議；**完整 PDF 是獨立報告檔案**，包含更詳細的逐張原始照片、改善模擬與相關說明。

**為什麼還要 PDF？**  
摘要適合快速閱讀與決定行動，PDF 適合保存或檢視完整圖文證據。完整 PDF 依目前主站權限設計僅提供喵戶本人取得。

**網站「開始檢測」是不是已經能做真實分析？**  
程式保留的單獨檢測入口仍可能建立示範報告。真實 AI 報告應從「我的 3D 房間」上傳居家影片並等待背景 Worker 完成，不應混淆。

**框線代表 AI 偵測已百分之百正確嗎？**  
不代表。PDF 案例中的橘色實線是 AI 估計危害範圍；綠色虛線是模擬圖的場景對位範圍。需要依實際現場確認。

**45.34% 是整份報告的處理時間嗎？**  
不是，僅為固定六件 Image Edit 的受控測試結果。

**Worker 是正式雲端長期常駐嗎？**  
所引用單筆驗收為本機 Linux AMD64 Docker Worker 串接正式網站及雲端服務，不宣稱長期正式營運負載已驗證。
