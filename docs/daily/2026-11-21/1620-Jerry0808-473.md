## 可重現的比較

執行 `npx vitest run src/lib/home-safety src/lib/storage src/app/api/homes`。報告測試以同一 attempt 的兩個並發圖片請求模擬冷實例，對每筆授權查詢保留 Owner 檢查。將新測試套到主線舊實作時，兩個請求實際下載新版清單兩次。新實作只讀一次且不讀 HTML。接著讀取新版 JSON 未列入、完整 HTML 有引用的圖片，實際讀 HTML 一次，通過後才下載圖片。超過 30 秒會重讀清單。只有伺服器同一實例共享記憶體，保留最多 32 筆與短期失效。

| 情境 | Before | After |
| --- | ---: | ---: |
| 兩個冷並發合法圖片請求，MediaStore download | 4 | 3 |
| 兩個冷並發合法圖片請求，report-view.json reads | 2 | 1 |
| 兩個冷並發合法圖片請求，report.html reads | 0 | 0 |
| 小型 Blob 每次 download 的一般 SDK 操作（無重試） | 2 HEAD＋1 GET | 1 GET |
| 兩個冷並發合法圖片請求，依 SDK 呼叫推算 Azure HTTP（無重試） | 12 | 3 |
| 未展開的摘要圖片標籤 | 0 | 0 |
| 展開一組完整對照的圖片標籤 | 4 | 4 |

SDK 以安裝版本的 `Clients.js` 核對，舊 `exists()` 呼叫 `getProperties()`，無明確大小的 `downloadToBuffer()` 又呼叫一次。新路徑用 download stream；404 保留既有 null，其他錯誤保留失敗。SDK 在中斷後的內建重試可能增加實際 HTTP 數。

## 資產與部署驗收邊界

#561 既有報告第一組的 Before 1440×810／95,056 bytes，After 1672×941／1,845,312 bytes，兩張局部圖 26,072 與 35,986 bytes，四圖合計 2,002,426 bytes。After 佔這組約 92%。原圖完整保留，Before 優先、After 及局部延後載入；瀏覽器的 Lazy Loading 接近視口時也可能提前載入，桌面並排時不應預期節省 After bytes。本次未導入額外影像轉碼，以避免冷請求增加編碼成本及額外證據格式。

同樣四圖全部載入的 payload Before／After 一致。此輪縮減上游重複文件傳輸與等待往返。正式站旗標值、HTML TTFB、圖片 TTFB、首屏繪製時間、實體手機網路與 P50／P95 尚未確認。正式部署前請以同一報告、同一 Owner 及相同頻寬分別量測冷／暖請求，記錄第一張原圖完成、選取案例後首屏 bytes 與完整報告結果。

保留 `private, no-store`、每次 Owner／attempt 檢查、SHA-256、舊 HTML 回退及 PDF 路徑。無 schema、Worker、SAS 或共用資料變更。
