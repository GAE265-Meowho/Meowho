## 1. 命名與定位

| 項目 | 內容 |
|---|---|
| 名稱 | **MeowHQ**（Meow Headquarters｜喵星總部） |
| 瀏覽器標題 | `MeowHQ｜喵星總部` |
| 命名理由 | 短、好記；「總部」可以自然容納未來新增的功能 |
| 使用者 | 系統管理員、管理員（依模組授權） |
| 網址 | **`/MeowHQ`**（與前台同網域）；`/meowhq` 等大小寫不同的寫法自動導向 `/MeowHQ`；舊路徑 `/mh-console-8k2p` 停用 |
| 入口與收錄 | 前台頁面不放任何後台入口；後台頁面設定不讓搜尋引擎收錄（沿用現行做法） |
| 登入 | 需要 Google 登入。未登入 → MeowHQ 登入頁（Google 登入）；登入後不是管理員 → 顯示「找不到頁面」，不透露這裡是後台 |
| 使用裝置 | **桌機優先，手機可用**：審核、停權等單筆處理在手機上要能完成；寬表格可橫向捲動 |

## 2. 視覺風格：Nordic Meow（北歐）

簡約、有質感，貓咪元素作為小巧點綴。前台 Meow Home 使用 Cozy Cat Nook 風格；MeowHQ 使用獨立的 Nordic Meow 風格。

### 2.1 色彩（文字與底色對比度皆 ≥ 4.5:1）

| 用途 | 色碼 | 說明 |
|---|---|---|
| 象牙白底色 | `#FAF7F0` | 頁面背景；卡片 `#FFFFFF` |
| 主要文字 | `#2F2B27` | 暖炭灰，不用純黑 |
| 次要文字 | `#6B655D` | 說明文字、時間 |
| 邊線 | `#E7E1D6` | 卡片、表格分隔 |
| 鼠尾草綠（主要動作） | `#4F6E57` | 主按鈕、選中狀態；按鈕上用白字 |
| 鼠尾草淺底 | `#E5ECE4`＋文字 `#3D5A44` | 「正常」「已上架」等狀態標籤 |
| 焦糖橘（強調、提醒） | `#A0521F` | 待辦數字、提醒文字 |
| 焦糖淺底 | `#F6E7D8`＋文字 `#7A3E12` | 「待審」「草稿」等狀態標籤、提醒框 |
| 危險動作 | `#9E3B2E` | 撤銷、停權；一定搭配文字，不只靠顏色辨識 |

### 2.2 字型
Noto Sans TC，字重 400／500／700；不使用襯線字。

### 2.3 貓咪點綴
- Logo：「MeowHQ」字樣上方一對細線貓耳。
- 空白狀態：線條畫的睡貓（例如「目前沒有待辦」）。
- 載入中：小貓掌印。
- 圖示一律使用細線條圖示，不使用 emoji（現有後台的 emoji 一併替換）。

## 3. 角色與權限（已確認）

- 系統管理員：全部模組；可有多位，不能移除最後一位；第一位以 SQL 指定；不能被停權，須先由另一位系統管理員撤銷其身分。
- 管理員：只能看到並使用被授予的模組；權限每次操作時重新判斷，撤銷立即生效。
- 停權對象：管理員（有「用戶權限管理」權限者）只能停權**貓友**與**貓戶長**；停權管理員只能由系統管理員執行，並同時收回其所有模組授權。管理員打開管理員帳號時，「停權」按鈕鎖住並註明「需由系統管理員處理」。
- 黑名單只有系統管理員能執行，對象只限貓友與貓戶長（R9）；所有管理動作寫入稽核日誌並需填原因。

## 4. 畫面

### 4.0 版面與導覽

| 區域 | 內容 |
|---|---|
| 頂列（左） | Logo「MeowHQ」（細線貓耳） |
| 頂列（右） | 通知鈴鐺＋未讀數；登入者頭像（點開：名稱、角色、登出） |
| 側欄 | 依使用頻率排列：首頁（待辦總覽）→ 檢舉與內容審核 → 用戶權限管理 → 商品 → 知識管理 → 虛擬體驗元件管理 →（分隔線）→ Admin 授權（僅系統管理員）；只顯示有權限的模組 |

### 4.1 首頁：待辦總覽

登入後的第一個畫面。只顯示登入者有權限的模組，每個模組一張卡片，列出待處理數量，點擊直接進入該模組並套用對應篩選。

| 模組 | 待辦項目（預設） |
|---|---|
| 虛擬體驗元件管理 | 草稿中、尚未上架的元件 |
| 知識管理 | 草稿中、尚未發布的文章 |
| 用戶權限管理 | 待審中途認證、補件已回覆 |
| 檢舉與內容審核 | 未處理檢舉、AI 標記待審 |
| 商品 | 待審核的匯入商品、參考價超過 3 個月未更新 |
| Admin 授權（僅系統管理員） | 不顯示待辦數，顯示最近的授權變更 |

- 卡片下方：登入者自己最近 5 筆管理動作（完整稽核日誌只有系統管理員看得到）。
- 待辦數為 0 的模組仍顯示卡片，標示「目前沒有待辦」。
- 統計數字不放首頁：導購成效在「商品」，平台統計在「Admin 授權」。

### 4.2 模組與畫面

| 模組 | 畫面 | 權限 |
|---|---|---|
| 虛擬體驗元件管理 | 元件列表、上傳、預覽、上下架、版本 | 授權制 |
| 知識管理 | 文章列表、編輯、草稿／發布、版本 | 授權制 |
| 用戶權限管理 | 帳號列表與詳情（貓友、貓戶長）、停權、中途認證、黑名單 | 授權制（黑名單限系統管理員） |
| 檢舉與內容審核 | 檢舉列表、AI 審核標記、下架 | 授權制 |
| 商品 | 寵物飼料、用品、參考價、導購成效 | 授權制 |
| Admin 授權 | 管理員授權矩陣、稽核日誌、平台統計、系統設定 | 僅系統管理員 |

### 4.3 系統設定（Admin 授權模組內）

| 設定 | 說明 |
|---|---|
| 網站標誌 | 從 3 款 logo 選一款作為前台站台標誌（沿用現有功能） |
| Demo 加速模式 | 虛擬飼養 1 天＝5 分鐘 |

> 之後若需要首頁橫幅、公告，再新增「網站外觀」模組，並把網站標誌移過去。

### 4.4 通知

- 只用站內通知：頂列右側小鈴鐺＋未讀數，即時更新。
- 通知只發給**有該模組權限**的管理員（例如新的中途認證申請 → 有「用戶權限管理」權限的人；新的檢舉 → 有「檢舉與內容審核」權限的人）。系統管理員收到全部。
- 現有程式「通知所有管理員」的做法需改為依模組發送。
- 不做 Email、Web Push（與 SRS FR-11-03 一致）；LINE 通知列為未來延伸（§7）。

### 4.5 稽核日誌

- 永久保留；任何人（含系統管理員）都不能修改或刪除，只能查詢與篩選。
- 篩選條件：操作者、動作類型、對象、日期區間。

### 4.6 處置操作（停權、撤銷、下架）

原則：操作者已是被授權的管理員，由管理員自行把關；**不跳確認視窗、不提供「復原」按鈕**，但**每個處置都必須填寫原因**，原因寫入稽核日誌。

| 操作 | 方式 |
|---|---|
| 停權／解除停權 | 帳號詳情的「停權中」checkbox。勾選或取消勾選時，下方展開必填「原因」欄位（停權另可選期限，預設「直到手動解除」），按「儲存」才生效。停權前，checkbox 旁直接顯示影響說明（例：「將自動婉拒 3 筆審核中申請並通知對方」）；解除停權時提示「已婉拒的申請不會恢復」 |
| 撤銷模組授權、撤銷中途徽章 | 取消勾選或按「撤銷」，必填原因後儲存 |
| 下架內容、元件下架 | 按「下架」，必填原因後儲存；可重新上架（同樣需原因） |
| 加入黑名單（僅系統管理員） | 必填原因，**並輸入對方的 Email**（與帳號相符）才能儲存，防止點錯列；移出黑名單同樣需原因 |

### 4.7 操作回饋

| 情況 | 方式 |
|---|---|
| 填寫原因 | 原因欄上方提供常用原因快選標籤，點選自動填入，可再補充文字。停權：疑似販售貓咪、詐騙、辱罵或騷擾、不實資料、其他；下架：非貓內容、不當內容、重複、其他；撤銷授權／徽章：職務異動、資料不符、其他（各模組可再調整） |
| 成功 | 右下角提示約 4 秒（例：「已停權 [名稱]」），附「查看紀錄」連結；手機改從底部出現 |
| 失敗 | 保留表單內容；儲存按鈕旁以白話說明原因（例：「網路中斷，請再試一次」），不顯示錯誤代碼 |
| 操作途中權限被撤銷 | 提示「你的權限已變更」，自動回到待辦總覽 |

### 4.8 列表體驗

| 項目 | 規則 |
|---|---|
| 詳情開啟 | 桌機：右側面板開啟，列表保留在左側，可直接點下一筆；手機：整頁開啟 |
| 搜尋與篩選 | 列表上方一個搜尋框＋篩選標籤（例：待審、已核准）；篩選條件寫入網址，複製連結給其他管理員可看到相同結果 |
| 排序 | 待處理佇列（檢舉、中途認證、AI 標記）預設「等最久的在前」；其他列表「最新的在前」 |
| 分頁 | 每頁 20 筆 |
| 批次處理 | 只開放低風險操作（檢舉批次標為「無需處理」、匯入商品批次審核通過）；停權、黑名單、撤銷授權不開放批次 |

### 4.9 手機版

手機的主要情境是「收到通知 → 處理一筆 → 離開」。

| 類別 | 規則 |
|---|---|
| 手機必須順手 | 鈴鐺通知 → 直接開啟該筆詳情；中途認證核准／要求補件／退回；檢舉處理（下架／無需處理）；停權 checkbox＋原因 |
| 詳情頁 | 主要動作按鈕固定在畫面底部，拇指可及；觸控目標 ≥ 44px |
| 列表 | 表格在手機改為卡片列表（每張卡片顯示名稱、狀態、時間） |
| 只建議桌機 | 3D 元件上傳、商品匯入、授權矩陣編輯、稽核日誌進階篩選：手機可瀏覽，操作按鈕旁提示「建議使用桌機操作」 |

### 4.10 空白、載入、錯誤狀態

| 狀態 | 呈現 |
|---|---|
| 空白（沒有資料） | 線條睡貓插圖＋一句說明＋下一步按鈕（例：「目前沒有待審的中途認證」＋「回待辦總覽」） |
| 篩選後沒有結果 | 不放插圖，文字「沒有符合條件的資料」＋「清除篩選」 |
| 載入中 | 列表與卡片顯示骨架（灰色佔位條）；超過 1 秒仍未完成，骨架上方顯示小貓掌印動畫 |
| 載入失敗 | 區塊內顯示「載入失敗」＋「重試」，不影響頁面其他區塊 |
| 網路中斷 | 頂列下方出現橫幅「目前離線，恢復連線後會自動更新」；儲存按鈕停用 |
| 沒有權限 | 該模組網址直接顯示「找不到頁面」（與未授權進入 MeowHQ 相同） |
| 權限在操作途中被撤銷 | 見 §4.7 |

設計稿：「後台管理」畫布（Admin 授權、用戶權限管理、中途認證、虛擬體驗元件管理）；風格將改為 Nordic Meow，並補上首頁。

## 5. 已確認的業務規則

| # | 規則 |
|---|---|
| R1 | 停權時，該帳號送出的、以及其貓收到的審核中領養申請自動婉拒並通知對方 |
| R2 | 中途徽章授予「貓戶」；撤銷後立即失去認證中途權限（含查看領養人評分） |
| R3 | 虛擬體驗元件分三類：通用 3D 貓模型、場景與道具、風險點示範動畫；個別貓的虛擬貓不在元件庫 |
| R4 | 商品分「寵物飼料」「用品」兩類 |
| R5 | 後台通知只發給有該模組權限的管理員；系統管理員收到全部 |
| R6 | 稽核日誌永久保留，任何人都不能修改或刪除 |
| R7 | 管理員只能停權貓友與貓戶長；停權管理員限系統管理員並同時收回模組授權；系統管理員不能被停權 |
| R8 | 解除停權不會恢復已婉拒的領養申請，對方需重新申請；解除停權時畫面提醒此點 |
| R9 | 黑名單只限貓友與貓戶長：管理員、系統管理員都不能被加入黑名單；須先由系統管理員撤銷其管理員身分。也不能預先封禁尚未登入過 Meow Home 的 Google 帳號（2026/10/29 確認） |
| R10 | 停權期限必須是未來的時間；「直到手動解除」不受此限（2026/10/29 確認） |
| R11 | 同一帳號同時只能有一筆生效中的停權，不能重複停權；要改期限須先解除再重新停權（2026/10/29 確認） |
