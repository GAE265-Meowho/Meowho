## 1. 頁面結構

### 1.1 四個區塊

`/MeowHQ/assets` 頁面上方以分頁（tab）呈現四個區塊，網址用 `?tab=` 保存，重新整理後仍停在同一區塊。

| 順序 | 區塊 | 網址參數 | 狀態 | 內容 |
|---|---|---|---|---|
| 1 | 貓咪 | `?tab=cats`（預設） | 本規格書 §2 起 | 貓咪模型列表；每隻貓有自己的頁面與工作頁 |
| 2 | 室內空間 | `?tab=rooms` | 規劃中 | 房間、場景（如 `meowho_3d_room`）；第一版只顯示空白狀態 |
| 3 | 生活用品 | `?tab=items` | 規劃中 | 碗、貓砂盆、玩具、貓抓板等道具；第一版只顯示空白狀態 |
| 4 | 其他 | `?tab=others` | 規劃中 | 風險點示範動畫等不屬於前三類的元件；第一版只顯示空白狀態 |

- 每個區塊各自有列表、搜尋、狀態篩選；列表共用 T-HQ-08 的列表元件。
- 規劃中的三個區塊：標題旁顯示「規劃中」標籤，內容為空白狀態：「這個分類還在規劃，之後會在這裡管理」。不顯示上傳按鈕。
- 頁面標題旁的待辦數（首頁 §4.1 卡片）＝四個區塊中「草稿中、尚未上架」的總和；第一版只有貓咪有資料。
- 手機：分頁可橫向捲動；上傳與生成按鈕旁提示「建議使用桌機操作」（01 §4.9）。

### 2.3 貼圖工作頁（套貼圖、產生）

網址 `/MeowHQ/assets/cats/<id>/studio`。這個頁面做的是「讓這隻貓長出自己的樣子」，由上到下四個區塊：

**① 新增與照片**（從列表按「新增貓咪模型」會直接進到這裡，名稱與照片是第一步）

1. 名稱（必填）、類型（本期固定範本貓）、上傳照片；年齡、體重、備註為選填（沿用 Cat Studio 的 profile）。
2. 顯示拍攝提示：**側拍、坐姿或站姿、拍到全身、背景越單純越好**（母體以單張照片為基礎）。
3. 照片檢查：只檢查格式（JPG／PNG／WebP）與大小（≤ 10 MB），不做 AI 辨識；不符合時顯示明確原因。
4. 儲存後狀態為「草稿」，**不會自動開始生成**；可換照片（換照片後貼圖需重新產生）。

**② 產生選項**，按 **「產生動作 glb」**（沿用 Cat Studio 的參數）：

| 選項 | 值 | 說明 |
|---|---|---|
| 照片角度 | 正面（預設）／左側／右側 | 側面照時，worker 會把母體轉到同方向再上色 |
| 補看不到的花紋 | 不補（預設）／虎斑 | 照片看不到的背部、側腹用程序化虎斑補上；之後可擴充其他花紋 |

送出後建立一筆生成任務，狀態變「排隊中」；已有排隊中或生成中的任務時，按鈕停用並顯示原因。

**③ 任務進度**

- 顯示目前狀態與步驟（照片去背 → 載入模型 → AI 上色 → 補花紋、眼皮邊 → 完成）、已經過時間、預估剩餘（AI 上色約 3~6 分鐘）。
- 頁面每 3 秒更新一次；離開頁面任務照跑，回來可看到最新狀態。
- 失敗時顯示原因與「重試」；重試沿用原照片，也可改選項再試。
- 排隊中超過 2 分鐘沒被領取時，提示「worker 可能沒有開啟，請確認 paint_worker 有在執行」（沿用 Cat Studio 的提示）。

**④ 套貼圖結果檢視**

- 左：原始照片；中：產出的貼圖（`paint_albedo.png`，可放大看）；右：套上貼圖的 3D 預覽（`CatPreview`，只有旋轉、縮放、動作選擇）。
- 貼圖來源：worker 輸出的是這隻貓自己的貼圖；網格、骨架、全部動作是共用的母體 `base_clips.glb`，預覽時把貼圖換上去（做法見 §2.4）。
- 「**匯出 GLB**」（選用）：在瀏覽器端用 `GLTFExporter` 把「換好貼圖的母體＋全部動作」輸出成單一 `cat.glb`，上傳後存放；不匯出也不影響預覽與上架。
- **貼圖版本：保留最近 1 版**（2026/10/31 Tina 確認）。重新產生成功時，目前使用的貼圖變成「上一版」（`paint_albedo_prev.png`），新貼圖成為目前版；再重新產生一次，更早的上一版就被丟掉。重新產生失敗時不動目前版。檢視區提供「改用上一版」按鈕（會與目前版互換，需填原因並寫稽核日誌）；沒有上一版時按鈕停用。
- 底部資訊：貼圖尺寸、生成耗時、使用的照片角度與補花紋、母體版本。
- 「**回到貓咪頁看動作**」按鈕：完成後的主要下一步。

### 2.4 貓咪頁（每隻貓獨立頁面，看動作）

網址 `/MeowHQ/assets/cats/<id>`。這個頁面專門用來看這隻貓會做什麼動作，也是上架前的最後確認。

**預覽做法（沿用 cat_studio 的 `/eye?mode=clips&cat=<id>`）**

| 項目 | 說明 |
|---|---|
| 模型來源 | 載入共用的母體 `base_clips.glb`（身體、骨架、眼球、全部動作），不是每隻貓各載一份 |
| 換貼圖 | 載入後走訪所有 mesh，材質名稱為 `cat_fur` 的，把 `map` 換成這隻貓的 `paint_albedo.png`（`flipY = false`、sRGB）；網址加時間戳避免快取 |
| 沒有貼圖時 | 尚未產生貼圖的貓（草稿、失敗）顯示母體預設貼圖，並在預覽上方顯示橫幅「尚未產生這隻貓的貼圖」＋「前往貼圖工作頁」 |
| 動作切換 | glb 內每個 animation 是一個動作；用 `THREE.AnimationMixer`，切換時 `crossFadeFrom` 淡入淡出 0.4 秒；預設播 `idle`（沒有 `idle` 才播第一個） |
| 眨眼 | 拉桿 0–1，控制形狀鍵 `blink_L`、`blink_R`；動作本身也會眨眼 |
| 眼睛 | 材質名稱 `cat_eye` 的眼球，換成 `cat_eye.js` 的自訂 shader（瞳孔、虹膜、角膜）；「看游標」開啟時眼睛跟著滑鼠轉，最大 28° |
| 視角 | 滑鼠拖曳旋轉、滾輪縮放；預設相機對準全身（target `(0, 0.23, 0)`，相機 `(0.95, 0.45, 0.95)`；比 cat_studio 拉遠、抬高，因為後台預覽框較寬扁、貓連頭約 0.5 m，原本會切到頭）；有「重設視角」 |
| 光線 | `RoomEnvironment` 環境光＋一盞方向光；曝光可調（影響瞳孔大小） |
| 狀態列 | 顯示眼球數、骨頭數、形狀鍵名稱，載入失敗時顯示原因 |

- 眼睛顏色、瞳孔細部參數（虹膜大小、角膜凸起、折射率、異色瞳）是 Cat Studio 的調校工具；後台第一版**只保留**瞳孔寬窄、環境亮度、眨眼三個控制，其餘使用預設值，之後再視需要補入。

**頁面內容**

| 區域 | 內容 |
|---|---|
| 頂部 | 貓咪名稱、狀態標籤、「前往貼圖工作頁」、「上架」或「下架」按鈕 |
| 主區 | 3D 預覽（上述功能） |
| **動作清單**（預覽旁） | **列出動作庫全部動作**（§2.6）：已完成的是可點的按鈕，點了就播放；規劃中的（吃飯、上廁所、撒嬌、跳躍、休息、理毛）灰色、標示「規劃中」且不能點；目前播放中的高亮 |
| 動作控制 | 目前動作名稱、時長；循環播放；播放／暫停；速度 0.5×／1×／1.5× |
| 資訊 | 原始照片縮圖、照片角度與補花紋、母體版本、建立者與時間 |

- 動作可用網址指定：`/MeowHQ/assets/cats/<id>?clip=walk`，方便分享或截圖給組員看某個動作。
- 母體 glb 更新後，動作清單自動出現新動作（見 §2.6），不用重新產生貓。
- 操作：上架、下架、刪除草稿；均需必填原因並寫入稽核日誌（沿用 01 §4.6）。匯出 GLB 在貼圖工作頁。
### 2.5 狀態

```
草稿 → 排隊中 → 生成中 → 已完成 → 上架中（已上架）⇄ 已下架
                    └→ 失敗 → （重試）→ 排隊中
```

| 狀態 | 代碼 | 說明 |
|---|---|---|
| 草稿 | `draft` | 已上傳照片，尚未產生 |
| 排隊中 | `queued` | 任務已建立，等 worker 領取 |
| 生成中 | `running` | worker 正在跑；顯示目前步驟與進度 |
| 已完成 | `ready` | 已產生 glb，尚未上架，可預覽 |
| 失敗 | `failed` | 顯示失敗步驟與訊息；可重試 |
| 已上架 | `published` | 前台可選用 |
| 已下架 | `unpublished` | 前台不可選用；可重新上架（需原因） |

生成任務的步驟（`step`，與 `paint_worker.py` 現有顯示一致）：照片去背 → 載入模型（第一次約 1~3 分鐘）→ AI 上色（約 3~6 分鐘）→ 補花紋、眼皮邊 → 完成。

### 2.6 動作庫

動作屬於母體，**不是每隻貓各做一份**。每隻貓用的是共用的母體 `base_clips.glb`，因此「所有貓自動擁有動作庫的全部動作」；新增動作後，不需要重新產生任何一隻貓。

| 動作代碼 | 顯示名稱 | 狀態 | 備註 |
|---|---|---|---|
| `idle` | 待機 | ✅ 已完成 | 4 秒，呼吸、尾巴、耳朵、眨眼、轉頭 |
| `walk` | 走路 | ✅ 已完成 | 1 秒原地循環；位移由網頁端處理 |
| `sleep` | 睡覺 | ✅ 已完成 | 母雞蹲、閉眼、呼吸 |
| `eat` | 吃飯 | 規劃中 | |
| `toilet` | 上廁所 | 規劃中 | |
| `cuddle` | 撒嬌 | 規劃中 | |
| `jump` | 跳躍 | 規劃中 | |
| `rest` | 休息 | 規劃中 | 與 `sleep` 的差異：清醒、趴著 |
| `groom` | 理毛 | 規劃中 | |

- 後台在貓咪區塊提供「動作庫」子頁（唯讀清單）：動作代碼、名稱、狀態、所屬動作庫版本、時長。清單由程式內的動作定義（manifest）提供，不是在畫面上編輯。
- 補入新動作的方式：在 `stepC_clips.py` 新增 `clip_xxx` 函式並加進 `CLIPS`、更新 manifest、動作庫版本號 +1，重新輸出母體 `base_clips.glb`。
- 母體 glb 更新後，所有貓下次預覽就會看到新動作；只有「匯出 GLB」過的單檔貓才會落後，列表對這些貓顯示「可更新」，按「重新匯出」即可。
- 前台只用動作代碼播放；找不到的動作要退回 `idle`，不能報錯。

### 2.7 照片保存

- 原始照片永久保留（可重新產生、換選項重試時不必重傳），只有擁有該模型的人與有 `virtual_assets` 權限的管理員可讀取。
- 刪除貓咪模型時，連同照片、貼圖、匯出的 glb 一併刪除並寫稽核日誌（日誌本身不刪）。

## 4. 生成引擎（任務佇列＋獨立 worker）

網頁不執行生成，只負責建立任務與顯示結果。**worker 直接沿用 `cat_studio/paint_worker.py`，不改寫生成邏輯。**

```
後台頁面 ─(建立任務)→ 任務儲存 ←(輪詢領取)─ paint_worker（本機／日後 GPU VM）
                                              │ 去背 → AI 上色(A-3) → 補花紋與眼皮邊(A-3b)
後台頁面 ←(讀狀態與進度)─────────────────── └→ 寫出 paint_albedo.png、更新狀態
後台頁面 ─(預覽)→ 共用 base_clips.glb ＋ 換上這隻貓的貼圖
```

| 項目 | 說明 |
|---|---|
| worker 位置 | 第一版在 Tina 的電腦（需 GPU 與 Hunyuan3D venv）；之後可搬到 Azure GPU VM，網頁與資料表不用改。**Blender 只有重新輸出母體動作時才需要**，生成每隻貓不用 |
| 不能放的地方 | Vercel、Azure App Service：沒有 GPU，也無法跑數分鐘的長任務 |
| 領取方式 | worker 輪詢 `queued` 任務，原子地改成 `running`（避免兩個 worker 領到同一筆） |
| 逾時 | `running` 超過 30 分鐘且無更新視為卡住，可由管理員重試 |
| 金鑰 | worker 使用的 service role key 只放在 worker 的環境變數，不放網頁、不進 repo |

### 本機模式（先在 Tina 電腦預覽）

- 後台的儲存與任務介面（repository）有兩種實作：**本機檔案**與 **Supabase**，以環境變數切換。
- 本機檔案實作直接使用 Cat Studio 現有的資料夾格式（`adoption_cats/<貓咪ID>/photo.*`、`profile.json`、`paint_job.json`、`paint_albedo.png`），由 Next.js 的伺服器端程式讀寫，路徑由環境變數指定（例如 `CAT_STUDIO_ROOT`）。
- 好處：**現有 `paint_worker.py` 一行都不用改**就能被新頁面驅動；Cat Studio 原本的頁面也能同時看到同一批貓。
- 本機實作只在 `NODE_ENV=development` 啟用，不會隨 Vercel 部署生效。
- 切到 Supabase 時，worker 需增加一個「讀寫 Supabase」的實作（PR 4），生成邏輯不變。

## 5. 權限與稽核

## 8. 驗收（摘要，細項併入 02 測試計畫）

1. 有 `virtual_assets` 權限的管理員進入頁面，看到四個分頁，預設在「貓咪」；其他三個分頁顯示規劃中的空白狀態。
2. 上傳不合格式或超過 10 MB 的照片，會被擋下並顯示原因。
3. 上傳合格照片後建立草稿，不自動開始生成。
4. 在貼圖工作頁按「產生動作 glb」可選照片角度與補花紋；送出後依序顯示排隊中、生成中（含目前步驟）、已完成；失敗時顯示原因並可重試；離開頁面再回來，仍顯示最新進度。
5. 每隻貓有獨立的貓咪頁 `/MeowHQ/assets/cats/<id>`：套用這隻貓的貼圖，動作清單列出動作庫全部動作，已完成的可點、規劃中的灰色不可點；`idle`／`walk`／`sleep` 之間淡入淡出切換；眨眼拉桿與看游標有作用；`?clip=walk` 會直接播放走路。
5a. 尚未產生貼圖的貓，貓咪頁顯示母體預設貼圖與「尚未產生這隻貓的貼圖」橫幅，並可前往貼圖工作頁。
6. 補入新動作並更新母體 glb 後，已完成的貓預覽自動出現新動作，不需重新產生。
7. 上架、下架、刪除都必須填原因，且稽核日誌有紀錄。
8. 無權限者直接輸入網址，看到「找不到頁面」。
9. 前台找不到的動作代碼退回 `idle`，不報錯。
10. 本機模式下，不需修改 `paint_worker.py`，新頁面建立的任務就能被它領取並產出貼圖。
