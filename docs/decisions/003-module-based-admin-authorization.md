# 003 管理員權限改為「系統管理員按模組授權」
- 日期：2026-10-28
- 發起人 × 工具：Tina × Claude Code (claude-opus-5-5)
- 背景：SRS v1.0（FR-01-04、FR-15-01）原本的設計是「Google 登入＋白名單 Email」即為管理員，所有管理員權限相同。這有兩個問題：增減管理員必須改設定；而且無法只讓某人處理特定工作，例如只負責檢舉審核、不能動商品。目前程式（`0001_meow.sql`）的 `meow_profiles.role` 只有 member／admin 兩種，任何 admin 都能授權他人。
- 決定：
  - 分成兩種角色：**系統管理員**與**管理員**（名詞定義見根目錄 `GLOSSARY.md`）。
  - 第一位系統管理員以 SQL 指定（`docs/setup/SUPABASE_LLM_SETUP.md` §7），之後在後台內管理其他人。
  - 系統管理員可以有多位，但不能移除最後一位。
  - 系統管理員以「後台模組」為單位授權給管理員：

    | 後台模組 | 包含功能 |
    |---|---|
    | 虛擬體驗元件管理 | 3D 元件上傳、上下架、版本 |
    | 知識管理 | 知識庫文章 |
    | 用戶權限管理 | 帳號查詢、停權、中途認證、黑名單（加入黑名單僅限系統管理員） |
    | 檢舉與內容審核 | 檢舉處理、AI 審核標記 |
    | 商品 | 飼料與用品資料、參考價、導購成效儀表板 |
    | Admin 授權（僅系統管理員） | 管理員授權、稽核日誌、系統設定（Demo 加速） |

  - 授權變更、停權、黑名單、徽章授予或撤銷都寫入稽核日誌，並需填寫原因。
  - 撤銷模組授權或中途徽章後立即生效；權限在每次操作時重新判斷。
- 影響：
  - SRS 升為 v1.1（§2、FR-01-04、FR-01-08、FR-09-11、M15、§7）。
  - 程式需調整：`meow_profiles.role` 增加 `system_admin`；新增 `meow_admin_module_grants`、`meow_audit_logs`、停權與黑名單資料表；`meow_is_admin()`、`meow_set_admin()` 與 RLS 改為依模組判斷（見開發任務清單 T-15-06～T-15-09）。
  - 設計稿：「Meow Home 後台管理」畫布（Admin 授權、用戶權限管理、中途認證、虛擬體驗元件管理）。
- 替代方案（未採用的原因）：
  - 維持白名單：最簡單，但變更要改設定，權限全有或全無。
  - 固定角色（如審核員、營運）：規則清楚，但角色組合固定，新增工作就要改程式。
