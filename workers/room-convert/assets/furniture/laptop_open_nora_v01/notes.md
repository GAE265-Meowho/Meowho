# laptop_open_nora_v01

打開的筆記型電腦模型，來源照片 `reference/laptop_side.png`（612×408，透明背景）。

## 規格實測

| 項目 | 要求 | 實際 |
|---|---|---|
| 三角形 | 約 20,000 | 1,944，沒有用到減面 |
| .glb 大小 | 1.5 MB 以內 | 137 KB，無貼圖 |
| 寬 | 約 0.32 公尺 | 0.32（X） |
| 高 | 約 0.22 公尺 | 0.2195（Y） |
| 深 | 約 0.22 公尺 | 機身 0.22；含往後傾的螢幕為 0.297（Z：-0.187 到 0.11） |
| 開合角度 | 約 110 度 | 110 度 |
| 原點 | 底部中心的桌面高度 | 機身底面中心，y = 0 為桌面 |
| 螢幕方向 | 朝 +Z | 朝 +Z |
| 材質 | 只用 MeshStandardMaterial | `main`（#D4D5D8，粗糙度 0.45）、`trim`（#26272A，粗糙度 0.5） |

`trim` 用在螢幕、鍵床、鉸鏈和側面插孔。沒有品牌標誌。

## 品質關卡

- 輪廓 IoU 0.919（Tier 1），長寬比差 0.007，尺度差 0.039。
- 比對時把蓋子暫時調成照片的 115 度並縮短，交付的模型維持 110 度。比對相機由照片的消失點推算，距離近側約 1.12 公尺。
- 自相交 0 個頂點，轉台、多角度、零件覆蓋（10 個零件）和嚴格規格驗證都通過。
- 內部差異 0.39，偏高。主因是照片螢幕為白色，這裡依要求改成深色；這個數字不代表細節相符。
- 匯出後的 .glb 與 .ts 渲染 6 個視角幾乎逐像素相同：只有 1 個像素的色差超過 16。負向對照（旋轉 0.02 弧度）有數萬個像素改變。

## 推測的部位

照片是接近正側面，所以這些都無法驗證：

- 寬度：來自指定尺寸，不是照片量測。
- 鍵盤排列：照片只看得出約 5 到 6 排。14 欄的配置、空白鍵和方向鍵區的位置都是自訂的。
- 觸控板寬度：只有前後範圍來自照片。
- 螢幕正面：邊框寬度和圓角。
- 機身底面、背面，以及左側（這裡沒有做插孔）。

## 與照片的差異

- 開合角度：照片約 115 度，模型 110 度。
- 高度：照片約 0.194 公尺，模型 0.22 公尺，所以蓋子較長。
- 螢幕：照片為白色，模型為深色。
- 機身：照片是金屬質感，模型是不帶金屬感的淺灰色。
- 邊緣：機身上下緣是硬邊加底部內縮，沒有照片的連續圓滑倒角。生成器的 extrude 不支援倒角。
- 鍵帽：是開孔露出下方深色鍵床，鍵面比面板低 0.8 公釐，不是凸起的鍵。

## 流程調整

- 檔名是 `laptop_side.png`，不是指令裡的 `laptop_front.png`，因為這是資料夾裡唯一的筆電照片。
- 建模階段精簡為 5 個（blockout、structural、form、material、optimization）。
- 鍵盤用帶孔面板，因為生成器的重複系統只支援環形排列，這樣 .glb 也不需要 instancing 擴充。
- 生成器的 MeshPhysicalMaterial 已改寫成 MeshStandardMaterial。
- 材質證據步驟略過，顏色由指令指定。
- .glb 內的 userData 和 uv 已移除。

## 額度

- 這段期間 5 小時額度從 19% 到 35%（+16%），每週額度從 15% 到 17%（+2%），約 10.7 萬 tokens。
- 以上包含水杯之後的三則問答，所以略高於這件的實際用量。
