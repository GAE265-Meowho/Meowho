# litter_box_open_nora_v01

開放式貓砂盆模型，來源照片 `reference/litter_box_front.png`（387×516，透明背景，斜上方視角）。

## 規格實測

| 項目 | 要求 | 實際 |
|---|---|---|
| 三角形 | 約 10,000 | 2,968，沒有用到減面 |
| .glb 大小 | 1 MB 以內 | 82 KB，無貼圖 |
| 尺寸 | 長 0.50、寬 0.38、高 0.15 公尺 | 長 0.50（Z）、寬 0.382（X）、高 0.15（Y） |
| 貓砂 | 原指令比盆緣低 0.04，後改為盆高的三分之一 | 砂面 y = 0.05，盆緣 0.15 |
| 入口 | 較低的一側朝 +Z | +Z 盆緣降到 0.12，比砂面高 0.07 |
| 原點 | 底部中心的地面 | y = 0 為地面 |
| 材質 | 只用 MeshStandardMaterial | `main`（#D4D5D8，粗糙度 0.5）、`trim`（貓砂，#C9BFA6，粗糙度 0.95） |

盆壁厚約 5 公釐，盆底平整。零件：`tub`、`rim-band`、`litter`、`handle-tab`（-Z 有孔把手）、`entrance-lip`（+Z 帶溝槽低唇）。

## 品質關卡

- 輪廓 IoU 0.856（Tier 1），長寬比差 0.018，尺度差 0.069。比對相機由暴力搜尋擬合（方位 60、仰角 40），模型維持指定尺寸，沒有縮放。
- 內部差異 0.202（貓砂降低前是 0.194）。部分來自刻意的差異：照片是藍綠色，砂堆隆起。
- 8 個建模階段全部跑完，轉台、多角度、零件覆蓋和嚴格規格驗證都通過。
- 匯出後的 .glb 與 .ts 渲染 6 個視角逐像素相同，負向對照（位移 1 公分）有數萬個像素改變。
- 自相交檢查未通過：盆身 5 個頂點，落在內底轉角。盆身輪廓經驗證沒有交叉，判定為誤報，但檢查本身仍是未通過。

## 推測的部位

- +Z 入口：下彎的深度和寬度來自指令，照片的盆緣是完整一圈，沒有低入口。
- 盆底和外側背面、盆壁厚度、內底深度。
- 帶溝槽低唇：照片是整排細肋條，這裡簡化成 3 個方槽，位置改到入口側。
- 把手外緣比照片小，因為要控制總長在 0.50。

## 與照片的差異

- 顏色：照片藍綠色，模型淺灰。
- 貓砂：照片是不平整的砂堆，且只鋪中間；模型是平面、沒有顆粒，高度依使用者後來的要求改為盆高的三分之一。
- 平面輪廓：模型是標準橢圓，照片兩端收得更窄，盆壁也更斜。
- 入口：從側面看有點像倒水的出水口。

## 流程紀錄

- 盆身用旋轉殼體壓成橢圓，再把 +Z 盆緣往下彎。生成器不支援這個變形，數值存在規格的 `tubWarp`，並寫進 .ts 的 `warpTub`。
- 生成器的 MeshPhysicalMaterial 已改寫成 MeshStandardMaterial。
- 材質證據步驟略過，顏色由指令指定。
- surface 階段第一次生成失敗，批次腳本卻用舊渲染記了通過。已發現，補上規格、重新生成並重審，舊紀錄仍留在審查歷史中。
- .glb 內的 userData 和 uv 已移除。
